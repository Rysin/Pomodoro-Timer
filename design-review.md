# Stage 3 Design Review — SCRUM-1

## Summary

**Review approved by the user on 2026-11-21.** The updated requirements explicitly authorize Playwright as test-only tooling, and the architecture proposes bounded browser verification without runtime changes. This review replaces the prior recommendation to prohibit Playwright.

The proposed boundaries are acceptable: CSS remains the only application change; timer, DOM wiring, and notification behavior stay unchanged; Playwright is isolated to `tests/start-button.pw.ts` and `playwright.config.ts`, with Chromium-only execution and a `*.pw.ts` Vitest discovery boundary. No architecture correction is required. The user approved this review on 2026-11-21. That approval does **not** authorize an exact `@playwright/test` version, package installation, Chromium installation, or implementation.

## Strengths

- **Traceability and scope:** The architecture maps the exact `#000080` Start/Resume appearance and behavior-preservation checks to AC-1–AC-3. It limits the product implementation to `src/style.css`; `index.html`, `src/main.ts`, `src/timer.ts`, and `src/notifications.ts` remain unchanged.
- **Timer boundary:** `PomodoroTimer` owns deadline-based countdowns, its 250 ms refresh interval, duplicate-start protection, cleanup, and phase completion. Existing Vitest tests use fake timers/system time and cover pause/resume/reset, work-only counting, completion callbacks, and delayed completion.
- **Browser verification boundary:** The proposed `tests/start-button.pw.ts` and `playwright.config.ts` are separated from runtime source. Chromium-only execution against a local Vite server is proportionate to AC verification, and the test spec suffix is distinct from the installed Vitest default pattern.
- **Notification safety:** The architecture requires a test stub before app initialization and forbids real browser permission UI. Existing Vitest coverage already exercises unsupported, denied, and granted notification paths.
- **UI accessibility baseline:** The existing native button, accessible names, `role="timer"`, polite status region, focus-visible outline, responsive control wrapping, and white-on-navy contrast are to be preserved. The styling does not change timer text or status announcements.
- **Dependency/prod isolation:** `@playwright/test` is proposed only as a development dependency, with no runtime import or app wiring. The architecture defers version selection and installation, and calls for production-output inspection.

## Risks/Gaps

| Severity | Risk / gap | Mitigation |
|---|---|---|
| **Medium** | A browser-clock test can pass while missing time-boundary regressions if Playwright's clock is installed too late, real waits are used, or a single delayed interval tick is mistaken for normal one-second progression. Regressions include drift/delayed completion, duplicate completion, pause/resume time loss, or incorrect reset semantics. | Install the Playwright page clock before navigation; use its controlled time (not sleeps or 25-/5-minute waits). Assert the rendered countdown while running, then verify pause freezes remaining time, resume continues from that remainder, and reset restores the current phase duration without clearing the completed-work count. Fast-forward across work and break boundaries and assert each phase completes once, work increments count once, break does not increment it, and each next phase remains idle until manually started. Keep the existing Vitest fake-clock tests as unit-level coverage. |
| **Medium** | A test could accidentally invoke native notification permission UI or leak browser permission state. A stub installed after navigation would also miss the app's initial capability/permission reads. | Install a page-side `Notification` stub before app scripts run. Keep permission in a non-granted state, spy on the stub's request method and constructor, assert no request on load or phase completion, and assert only the explicit Enable notifications action reaches the stub. Do not call Playwright `grantPermissions`, invoke a native prompt, or rely on a real browser permission outcome. |
| **Medium** | Accessible-name assertions alone would not detect a lost keyboard focus indicator, narrow-viewport overflow, or an accidental status-region change that causes excessive announcements. | Use role/name locators for Start and Resume; exercise keyboard focus/activation and assert the focused button retains a visible focus outline. Include a narrow viewport/no-horizontal-overflow check. Preserve the existing semantic button, `role="timer"`, and polite status region; do not make the countdown itself announce each tick or change runtime accessibility markup. Include a manual assistive-technology/status-announcement check in implementation verification because browser DOM assertions cannot prove actual screen-reader announcement cadence. |
| **Medium** | A broad/custom Vitest include could collect Playwright tests, causing duplicate execution or runner/API incompatibility. The discovery claim is specific to the installed Vitest default. | Keep `tests/start-button.pw.ts` with the `.pw.ts` suffix, set Playwright `testMatch` to `**/*.pw.ts`, and do not broaden Vitest discovery. Confirm `npm test` collects only the existing Vitest specs after implementation; revalidate if Vitest version or configuration changes. |
| **Medium** | An unreviewed Playwright version may not support the proposed page-clock API or may not align with the installed Chromium binary. A browser install also downloads test tooling that is not needed by production. | At Implementation stage, propose an exact `@playwright/test` version and justify compatibility with `page.clock`; obtain explicit approval for that version and dependency/lockfile changes before installation. Install only Chromium after approval, using the Playwright version's matching browser setup. Keep the dependency in `devDependencies`, tests/config outside `src`, and no Playwright imports in runtime code. Inspect the production build output and dependency placement to confirm no Playwright runtime/bundle inclusion. |
| **Low** | The current app build type-checks only `src`; it does not type-check the proposed Playwright spec/config. | Do not treat `npm run build` or Vitest as type-check evidence for `*.pw.ts` or `playwright.config.ts`. Ensure the approved Implementation-stage verification explicitly validates browser-test loading/execution and reports this type-check limitation or supplies an approved targeted check. |

## Decisions

1. **Accept the bounded Playwright proposal in `architecture.md` for design purposes.** `@playwright/test`, `tests/start-button.pw.ts`, and `playwright.config.ts` remain proposed test-only assets; no runtime behavior, application architecture, or AC scope changes.
2. **Do not select or imply approval of an exact dependency version or installation.** The user's approval authorizes Playwright for browser verification only. Exact package version, package/lockfile edits, test script, and dependency installation require the Implementation-stage proposal and explicit approval.
3. Use Chromium only, with the local Vite web server and Playwright's matching browser setup after approval. Keep report/artifact output under the ignored `node_modules/.cache/` location; do not add browser binaries or reports to production output or source control.
4. Use Playwright's controllable page clock for accelerated completion, installed before navigation. Never wait real work/break durations.
5. Stub `Notification` before page initialization and assert only stub interactions; never request real browser permission. Keep the existing Vitest notification tests and app notification boundaries unchanged.
6. Preserve the Vitest discovery boundary: installed Vitest 5.1.1's default include is `**/*.{test,spec}.?(c|m)[jt]s?(x)`, which does not match `.pw.ts`. Playwright alone selects `**/*.pw.ts`; no Vitest include override is proposed.
7. Preserve semantic controls, keyboard behavior and visible focus, responsive layout, and status/live-region semantics without announcing every timer tick. Automated checks should cover keyboard focus and a narrow viewport; actual announcement cadence remains a manual accessibility check.
8. No `architecture.md` correction is required. It already captures the approved Playwright scope, proposed paths, clock/stub approach, discovery boundary, Chromium, and production isolation. Do not edit implementation, configuration, tests, package files, or dependencies during this review.
